# Copy for marketing sites

Read when you write or edit headlines, subheads, CTAs, section text, microcopy or any text a visitor reads on a marketing page.

## Hard rules

- No em dash or en dash in UI or marketing text. Allowed in code comments.
- Never invent a fact: number, client, testimonial, deadline, badge. If data is missing, ask, or write a simpler sentence without it.
- Claim only what the code, the commercial guide and release notes support. No outcome promises.
- Plan names, prices and capabilities come from the source of truth, not the copywriter.
- No customer counters, no testimonial without written permission, no client logos.
- No licensed third-party instruments or trademarks by name without permission.

## Headline, subhead, CTA

- Headline: name the precise pain or the concrete result in the visitor's vocabulary. A precisely named pain sells more than the category.
- The headline must hold without emphasis. No highlighted word.
- Subhead: one support sentence that adds what the headline lacks (who it is for, how). Do not repeat the headline.
- CTA label: verb plus object ("Start free trial", "See pricing"). One primary CTA per view, one secondary.
- Tell the next step. Do not hide cost or commitment.
- Add an arrow only when the action is "advance".
- Competitor test: if a competitor could sign the sentence unchanged, rewrite it.
- 5-second test: a visitor on the hero understands what it is, who it is for and the next step.
- Layperson test: the sentence makes sense to someone who does not run the business.

## Specificity over adjectives

- Replace an adjective with the capability it stands for.
- Chain verified capabilities as clauses. Each clause must be a checkable feature.
- State plan-limited quotas where the price appears.
- Use names the visitor already recognizes, not internal terms.
- Prefer active voice.

## Proof

- Only verifiable proof: a real integration, a price, what a plan includes, a security fact you can show.
- Source every number. An unmeasured number ("cuts churn by 60%") is banned.
- Unsourced authority ("experts recommend", "the preferred system of") is banned.
- When there is no proof, say less.

## Sounds like AI: strongest signals

One occurrence calls for a rewrite.

- Staged contrast: "not just X, it's Y", "more than a tool", "it's not about X, it's about Y". State Y directly.
- Punchline on its own line: "Simple as that.", "And the best part:", "No hassle.", "That's it." Cut.
- Slogan with no content. Replace with what the product does.
- Announcing the point before the point: "It's worth noting that", "It is important to highlight", "Imagine a world where". Start with the point.
- Objection nobody raised: "And no, you don't need to be a tech expert."

## Sounds like AI: rhythm and inflation

- Automatic triplet ("fast, secure and intuitive") when the content has two or four items. Use the number the subject has.
- Three consecutive sentences with the same opening ("With [Brand], ...").
- All sentences the same length, joined with "and".
- Showcase verbs: revolutionize, transform, empower, elevate, optimize, leverage, streamline.
- Brochure adjectives: complete, robust, innovative, cutting-edge, intuitive, powerful, "complete solution", "everything in one place".
- Decorative trailing participle: "ensuring more security", "providing peace of mind".
- "Serves as" or "acts as" in place of "is".
- Formatting: bold on every sentence, uppercase titles with emoji, arrow on every button, Title Case everywhere.
- Conversation residue: "Sure!", "Great question", "I hope this helps".
- Text that describes itself: "In this section you will discover".

## Tone

- Plain, direct, concrete. Write like a person explaining to a colleague.
- Vary sentence length. Use commas and periods where speech breathes.
- Read it aloud. If you would not say it, rewrite it.

## Microcopy

- Button: action plus object ("Save note"). Confirm with the same verb ("Note saved"). One concept, one name through the flow.
- Error: what failed, why (if known and useful), how to proceed. No internal code as the main sentence, no apology.
- Empty state: say which kind (first use, no result, filter, no permission, failure). One line.
- Destructive action: name the object and consequence; the button repeats the action. Never "Yes" or "OK". Prefer undo when safe.
- Loading: name the operation. Progress bar only if progress exists.
- Forms: fixed label (the placeholder is only an example); state the required format before submit; the error sits beside the field and says how to fix it, without blame.
- Subtitle only if it informs.
- Toggle helper: open with the current state, say the effect and what the other position does.
- Sensitive data stays out of toasts, push, email subjects and previews. Access denied does not confirm a record exists.

## Localization

- One whole sentence per key. Never concatenate fragments.
- Variables as `{name}`. Do not build plurals or word order by hand.
- Leave room for the longest language to grow, and test that locale at every width.
- The banned-signal list was written for one language and translated. Look for the equivalent patterns in each language.

## Checklist

Before:
- [ ] Sources for every claim are known.
- [ ] Audience, pain and next step are named.

After:
- [ ] No em or en dash.
- [ ] No staged contrast, punchline line, slogan with no content, announced point.
- [ ] No triplet by reflex, repeated openings or uniform sentence length.
- [ ] No showcase verb or brochure adjective.
- [ ] Every number and claim is sourced.
- [ ] Competitor test, 5-second test and layperson test pass.
- [ ] Read aloud once.
- [ ] Rewrite checked again for what survived (staged contrast returns most).
